You are IBM Bob 2.0 in Agent mode. Build the standalone product described in this file. Read this whole document before you write code. Implement the steps in order. ## 1. Locked decisions

- Language: Python 3.11 or newer. If `python3` is older than 3.11, stop and say so. Do not backport.
- Runtime dependencies: `pyyaml` only.
- Test dependency: `pytest` only.
- No web framework, no LLM client, no database, no message queue.
- One engine, two interfaces:
  - CLI: `python -m rgc`
  - Local UI: stdlib `http.server` bound only to `127.0.0.1`
- Five checkers run at the same time with `concurrent.futures.ThreadPoolExecutor`.
- A failure, timeout, or exception in one checker does not cancel the others.
- Every checklist contains exactly these five check ids, in this order:
  1. `pipeline_status`
  2. `workflow_config`
  3. `fc_etl`
  4. `flyway`
  5. `playwright_map`
- Citations are found by searching markdown. Never hardcode a citation line number in rules, code, or fixtures metadata.
- A GO result stays `pending_approval` until a human approves. The E2E trigger file is written only after approval.
- BLOCKED cannot be approved. Cancel never writes a trigger file.
- Run pytest and the CLI from the repository root.
- stdout of `rgc check` is one JSON document and nothing else. stderr is empty for a completed check, including NO-GO. Tracebacks are not user-facing output.

```yaml
  - from: a

  - from: b
    to: a
    relation: must_deploy_before
```

Closure of the repos named in a release:

- Ancestors: every node that can reach a named repo by following edges forward.
- Descendants: every node reachable from a named repo by following edges forward.
- Closure = named repos that exist in the graph, plus ancestors, plus descendants.
- A named repo that is not a graph node is not added to the closure. It is reported by the pipeline checker as `unknown_repo` when it is also absent from the catalog. See section 10.
- `bitbucket-db-migration` is not a graph node. It is never in `deploy_order`.

`deploy_order` is a topological sort of the closure subgraph only (edges whose both ends are in the closure). Use Kahn's algorithm. When several nodes have indegree 0, pick the lexicographically smallest id. The full story graph has one legal order:

```text

prompt-backend
user-stack-ansible
meridian-ui
workflow-service
nc-enterprise-ai-platform-etl-jobs
```

Naming only `meridian-gateway` already closes over all six nodes.

Cycle detection uses depth-first search and treats a self-edge as a cycle. On a cycle, return the `graph_cycle` validation result from section 5. Do not run checkers. Do not also require catalog membership for nodes `a` and `b`.

## 13. Flyway Scan checker

File: `rgc/checkers/flyway.py`.

For every closure repo, list `db/migration` through the workspace view. A missing directory contributes no files and is not an error.

Consider only file names matching:

- `V<digits>__<rest>.sql` for versioned migrations
- `R__<rest>.sql` for repeatable migrations

Ignore every other file name, including `V1.sql`.

### Destructive SQL

Scan versioned and repeatable files. Strip comments and single-quoted strings before matching, with a character scanner:

- `'` starts a single-quoted string. Inside it, `''` is an escaped quote. Replace the whole quoted span, including quotes, with spaces.
- `--` starts a line comment when not inside a string. Replace through the newline with spaces.
- `/*` starts a block comment when not inside a string. Replace through the closing `*/` with spaces. An unclosed block comment runs to end of file.
- Do not treat comment markers that appear inside strings as comments.

On the stripped text, case-insensitive word matches:

- `\bDROP\s+TABLE\b` → block
- `\bDROP\s+COLUMN\b` → block
- `\bTRUNCATE\b` → block
- `\bDELETE\b` whose statement (from `DELETE` to the next semicolon, or end of text) has no `\bWHERE\b` → block

`DELETE FROM users WHERE id = 1` passes. `SELECT 'DROP TABLE users'` passes. `-- DROP TABLE users` passes.

Finding code `unsafe_migration`, severity `block`, message `Unsafe migration statement in {relative_path}.`, repos `[repo]`, suggested fix `Remove destructive statements or replace them with an expand-and-contract migration.`

One finding per matching file, not per statement.

### Versions

Parse the integer after `V`. Duplicates → `duplicate_migration_version`, message `Duplicate Flyway version {n}.`, suggested fix `Give each migration a unique version number.`

Let the sorted unique versions be `nums`. If `nums` is non-empty and `nums != list(range(1, max(nums)+1))` → `migration_version_gap`, message `Flyway versions are not contiguous from 1.`, suggested fix `Number migrations contiguously from V1 with no gaps.`

Repeatable scripts do not affect version order. An empty migration set passes.

Pass summary: `Flyway: no unsafe migrations`.

## 16. Orchestrator

File: `rgc/orchestrator.py`.

```text
def run_release(release, checkers=None, timeout_seconds=5.0) -> Checklist
```

Default checkers are the five production checkers, submitted together on one `ThreadPoolExecutor(max_workers=5)`.

Each checker receives an immutable context: the release, closure, deploy order, workspace view, catalog, and `ci_dir`. Checkers must not mutate shared state.

Per-checker timeout is `timeout_seconds`. If `future.result(timeout=...)` raises `TimeoutError`, that check is:

```text
status: blocked
code: checker_timeout
message: Checker timed out.
suggested_fix: Re-run the check. The checker did not finish before the timeout.
```

The worker thread may finish later. Discard its result.

If a checker raises any other exception:

```text
status: blocked
code: checker_error
message: Checker failed: {exception message}
suggested_fix: Fix the checker failure and re-run the check.
```

The other checkers are still collected. Never omit a check id. Never mark a check skipped.

Build the checklist with section 4's verdict rules, then run the citation engine.

Determinism: the same release inputs produce the same `to_dict()` output. No clocks, randomness, or unordered set iteration in serialized output.

`run_release_file(path, timeout_seconds=5.0) -> Checklist` loads a manifest, applies section 5 validation, and on success runs the checkers.

## 17. Human gate

File: `rgc/gate.py`.

`check` writes only:

- `{out}/checklist.json` — checklist `to_dict()`
- `{out}/gate.json`

```json
{
  "state": "pending_approval",
  "release_id": "safe"
}
```

`state` is `blocked` when the verdict is `no_go`, otherwise `pending_approval`.

`check` deletes `{out}/e2e-trigger.json` if it exists, including after a previous approval. A new check invalidates an old approval.

`approve(out_dir)`:

- Missing `gate.json` or `checklist.json` → exit 1, stderr `run not found`, no file created.
- `state` is `approved` → exit 0, leave the existing trigger bytes unchanged, stdout is the trigger JSON.
- `state` is `pending_approval` and checklist `verdict` is `go` → set state to `approved`, write the trigger, exit 0, stdout is the trigger JSON.
- Any other state, including `blocked` and `cancelled` → exit 1, stderr `approval rejected`, do not create a trigger.

Trigger JSON, key order fixed, no timestamps:

```json
{
  "release_id": "safe",
  "approved": true,
  "folders": ["backend", "etl", "gateway"],
  "estimate_seconds": 260,
  "estimate_display": "4m 20s"
}
```

Use the checklist `e2e` values. `folders` stays sorted.

`cancel(out_dir)`:

- Missing run → exit 1, stderr `run not found`.
- `pending_approval` → state `cancelled`, exit 0, stdout `{"cancelled": true}`, no trigger file.
- `cancelled` → exit 0, same stdout, no trigger file. Idempotent.
- `approved` or `blocked` → exit 1, stderr `cancel rejected`, trigger file untouched.

stdout JSON for approve and cancel uses indent 2 and a trailing newline. stderr is the single phrase above and a newline, with no traceback.
